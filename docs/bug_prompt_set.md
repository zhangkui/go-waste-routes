# Bug Prompt Set

`bug_category` 仅使用：`concurrency`、`nil`、`slice`、`error`、`context`、`defer`、`其它`

## Bugfix

1. **BUG-002 / error**：我这边看路线管理有个问题，先调整站点顺序，再改站点的预估收运量后去保存，系统还是按旧的汇总结果去判断超限；明明当前编辑后的路线还在允许范围内，却还是被拦住，路线根本保存不进去，排班也只能反复改站点和数量。当前看起来是同一条路线在编辑、校验、保存这条链路里没有对上。

2. **BUG-003 / error**：任务执行这块有个异常，任务领取后进入跳过流程时，用户按流程选原因、补备注、再上传现场照片，但只要原因不是预设项，系统还是能让它继续往下走；最后同一条任务的跳过结果、备注和附件经常对不上，异常记录也不完整。问题是同一条跳过链路里，原因校验和后续保存状态没有一起收住。

3. **BUG-004 / error**：任务编号生成这块有点乱，同一天里连续新建、补建、重新提交同一类任务时，编号本来应该沿用同一套规则，但现在不同入口生成出来的前缀和序号不一致；结果同一天的任务单号混在一起，人工查单和补单时很容易看错，现场对任务单据时也会对不上。

4. **BUG-005 / error**：称重记录在算净重时有个问题，毛重和皮重明明是同一组数据，但小数精度处理不稳定，界面上看到的结果和值班保存下来的值会对不上；这会直接影响称重结果判断，现场会怀疑是不是算错了，后面再看同一条记录时也会有争议。

5. **BUG-006 / error**：异常判断这条链路有漏判，历史均值、当前净重和临界比例一起变化时，刚好踩线的数据会被漏掉；本来应该进复核队列的记录没有进去，结果异常单子直接被放过去了，后面再补查时已经找不到被拦住的痕迹了。

6. **BUG-007 / error**：称重确认流程走完以后状态没收干净，记录看起来已经点过确认了，但实际状态没有稳定推进到已确认；页面像是处理完了，实际上这条记录还没真正闭合，后面再做审核或者追踪时会发现状态还卡着。

7. **BUG-008 / error**：路线到达时间这块有异常，站点停留时长为 0 的时候，站点顺序和时间表现会不稳定；本来应该原样保留的到达时间会出现偏差，前后看起来就不一致，调度人员拿着路线单去对时间时会发现不对劲。

8. **BUG-009 / error**：任务完成这条链路不干净，任务从领取、到达、收运一路走到完成时，最后提交里程和耗油量如果填了负数，系统没有稳定拦住；看起来任务已经结束了，但完成数据本身是脏的，后面统计和轨迹回看都会被带偏，最后的数据汇总也会跟着异常。

9. **BUG-011 / error**：称重记录驳回后有残留，原确认人和确认时间没有清干净；记录虽然已经显示成驳回了，但旧确认信息还留着，前后状态看起来不一致，回头看这条称重单时会误以为它还是确认过的。

10. **BUG-012 / error**：异常复核通过以后，驳回原因没有同步清空；这条记录虽然已经过了审核，但旧的拒绝内容还在，页面看起来还是像挂着一个未清理干净的状态，审核人员再看时会误判当前处理结果。

11. **BUG-018 / error**：称重更正记录保存时还有不一致，同样的更正内容从不同入口进来，原因字段前后空格没有统一清理；最后在列表和详情里显示得不一样，审计时也不好对照，同一条更正说明会看起来像两份不同文本。

12. **BUG-019 / nil**：任务接口这边的空值保护不稳，任务领取后再去做到达、完成这类动作时，传空对象或空任务标识的情况没有被稳定拦住；接口有时直接崩掉，有时又只返回普通业务错误，前端根本分不清是参数丢了还是任务本身有问题，用户会看到非常不稳定的反馈。

13. **BUG-020 / concurrency**：任务已经领取并进入执行中后，前端因为网络重试或重复点击，又把同一个“执行中”状态提交了一次。现在系统会把这次重试当成一次新的状态确认，把原始领取时间刷新成重试时间，页面看起来还在执行，但后续算工时、算超时和追踪轨迹都会被带偏。

## Diagnosis

1. **BUG-001 / error**：我这边想先帮忙分析一下，收运计划在节假日调整后为什么会出现预览日期和实际生成日期不一致的问题；现在看起来是同一条计划在预览时还能按前一工作日展示，但真正生成任务后日期却变了，前后对不上，操作人员就会按错日期排车。**先分析原因，不要改代码。**

2. **BUG-010 / error**：麻烦先确认下原因，查询不存在数据时错误类型为什么不稳定；底层明明是没查到，但上层拿不到明确的“未找到”语义，后面的业务分支就没法准确处理，同一类查询失败在不同页面上表现也不一样。**先排查，不要动实现。**

3. **BUG-013 / error**：我这边先看一下这个问题，路线从异常中断继续往下流转时，为什么状态没法正常进入取消态；现在流程卡在异常状态，后续就接不上了，调度那边也没法继续收尾。**先定位原因，不要提交修改。**

4. **BUG-014 / error**：先帮忙排查一下，异常判断在刚好命中临界比例时为什么会漏判；本来应该进复核队列的记录没进去，结果异常数据直接被放过去了，后面复核人员再追就已经晚了。**先分析原因，不要改任何文件。**

5. **BUG-015 / slice**：先定位一下原因，收运计划编辑周期规则后为什么会出现新版本保存把旧版本也带着改掉的问题；历史版本失真以后，回头看当时到底按哪版执行就分不清了，同一条计划的版本链也不可信了。**先帮忙分析，不要改代码。**

6. **BUG-016 / error**：我这边先帮忙分析一下，资源查询经过包装后为什么会把未找到语义丢掉；底层明明没查到，上层却只看到普通错误，后面没法继续做准确分支判断，同一个查询失败在不同入口上表现也不统一。**先排查原因，不要改文件。**

7. **BUG-017 / slice**：先看一下这个问题，统计合并时为什么会把原始数据一起改掉；合并后的展示看起来没问题，但基线数据已经被污染，后面再做二次合并或者前后对比时，结果会越算越偏，原始统计也回不去了。**先分析原因，不要动实现。**
